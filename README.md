# Linux.do 工具箱

Linux.do 的 Chrome Manifest V3 扩展，用于把帖子楼层复制或下载为 Markdown，并提供选中文本处理等阅读辅助功能。

扩展脚本只匹配以下页面：

- `https://linux.do/*`
- `https://www.linux.do/*`

## 功能概览

- **楼层操作**：在每个已渲染楼层的操作区添加“复制”和“下载”按钮。
- **主题双栏阅读**：桌面宽屏下将首帖正文和分页评论拆成两个独立滚动区，并隐藏主题页侧栏与时间轴。
- **已加载楼层导出**：从工具栏弹窗复制或下载当前页面已经加载的楼层，逐楼保留作者、时间和来源链接（可关闭元信息）。
- **选中文本工具**：在 Discourse 的选中文本工具条中提供 `base64` 解码和“去中文”，处理结果会复制到剪贴板。
- **图片链接处理**：导出 Markdown 时，可将当前楼层中匹配到的 `upload://` 图片链接替换为实际图片地址。
- **原生图片预览**：帖子正文图片点击后在全屏查看器中以原图打开，支持缩放、拖拽与快捷键，站点自带灯箱不可用时自动接管。
- **设置持久化**：弹窗中的设置保存在 Chrome 的同步存储中，并自动应用到当前页面。

## 安装

### 构建环境

从源码安装需要：

- Chrome 或其他支持 Manifest V3 的 Chromium 浏览器
- Node.js 20.19+ 或 22.12+，以及 npm

### 构建并加载

在项目根目录执行：

```bash
npm install
npm run build
```

然后在 Chrome 中完成以下操作：

1. 打开 `chrome://extensions/`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择构建生成的 `dist/` 目录。

也可以选择项目根目录加载。构建脚本会同时更新根目录中的 `content.js`、`popup.js`、`topic-events-bridge.js` 和 `dist/`，但不要直接加载 `src/` 目录。

### 更新扩展

源码更新后重新执行 `npm run build`，回到扩展管理页点击扩展的“重新加载”，再刷新已经打开的 Linux.do 页面。若 `package-lock.json` 或开发依赖有变化，先重新执行 `npm install`。

## 使用

### 复制或下载单个楼层

1. 打开一个 Linux.do 主题页面，并等待楼层加载完成。
2. 在目标楼层操作区点击“复制”或“下载”。
3. “复制”会把该楼层转换后的 Markdown 写入剪贴板；“下载”会生成类似 `主题标题_#3.md` 的文件。

按钮只会出现在当前已经渲染的楼层中。关闭“显示楼层复制 / 下载按钮”后，页面上的按钮会被移除。

### 使用主题双栏阅读

1. 在 Linux.do 主题页打开扩展弹窗，开启“主题正文 / 评论双栏阅读”；布局会在当前页面原地切换。
2. 视口宽度至少为 `1280px` 时，首帖正文显示在左栏，回复按 10、20 或 40 条分页显示在右栏，两栏可独立滚动。
3. 评论页码写入 `ldo_comments_page` 查询参数；浏览器前进/后退会恢复对应页，当前页和两栏滚动位置也会保存在本标签页会话中。

点赞、点赞用户、书签、分享、编辑、删除和回复等 Discourse 原生操作可直接在双栏中使用；原站楼层未加载时会在后台定位后执行，不会退出双栏。评论操作栏保留原站的点赞数和回复数，回复可直接在当前楼层下展开。投票等复杂嵌入仍会交给原页面处理。新回复只显示提示，不会轮询；楼层编辑、删除和恢复会通过当前页面已有的 Discourse 消息连接尽力同步，右栏同时提供手动刷新。

窄于 `1280px`、帖子数达到 10,000 的超大主题、请求失败或数据格式异常时，扩展会完整保留原始 Discourse 布局。双栏开关默认关闭。

### 复制或下载当前已加载楼层

1. 在 Linux.do 主题页点击浏览器工具栏中的“Linux.do 工具箱”图标。
2. 弹窗会显示主题标题和当前已加载的楼层数量。
3. 点击“复制当前已加载楼层”或“下载当前已加载楼层 (.md)”。

这里的“已加载”指页面 DOM 中当前可检测到的楼层，不等于服务器上的全部回复。插件会逐楼请求 Linux.do 的同源 `/raw/{主题 ID}/{楼层号}` 接口；遇到限流会自动重试，部分楼层失败时仍会输出成功的楼层并提示成功 / 失败数量。

### 解码 Base64 或去除中文

1. 在帖子中选中要处理的文本。
2. 在出现的 Discourse 选中文本工具条中点击 `base64` 或“去中文”。
3. 处理结果会自动复制到剪贴板。

`base64` 会先忽略空白并按 UTF-8 解码；“去中文”会去除中文字符及常见中文标点。没有选中文本、文本不是有效 Base64 或剪贴板写入失败时，页面会显示错误提示。

### 预览帖子图片

1. 开启“启用原生图片预览”后，点击帖子正文中的图片即可打开全屏查看器，优先使用 `a.lightbox` 指向的原图地址。
2. 鼠标滚轮或右下角 `+` / `-` 按钮缩放（指向指针位置），按住左键拖拽移动，双击图片在适应屏幕与放大视图之间切换。
3. 键盘快捷键：`+` / `-` 缩放，`0` 重置视图，`D` 打开原图下载，`Esc` 或点击背景关闭。

站点自带的灯箱可用时仍以原生行为优先；未拦截到点击（如双栏评论、动态插入内容）时，扩展会自动接管预览。图片外链、表情和头像不受影响。

## 功能开关

| 选项                      | 默认值 | 作用                                                      |
| ------------------------- | ------ | --------------------------------------------------------- |
| 主题正文 / 评论双栏阅读   | 关闭   | 在桌面宽屏主题页原地切换正文和分页评论双栏                |
| 每页评论数                | 20 条  | 双栏右侧每页显示 10、20 或 40 条评论                      |
| 显示楼层复制 / 下载按钮   | 开启   | 在已渲染楼层的操作区添加单楼层操作按钮                    |
| 启用选中文本 Base64 解码  | 开启   | 在选中文本工具条中添加 `base64` 和“去中文”                |
| 导出时保留来源元信息      | 开启   | 在 Markdown 中写入来源 URL、楼层号、作者和时间            |
| 替换 `upload://` 图片链接 | 开启   | 用当前楼层中找到的实际图片地址替换匹配的 `upload://` 链接 |
| 启用原生图片预览          | 开启   | 点击帖子正文图片打开全屏查看器，支持缩放、拖拽与快捷键    |

修改设置后会立即通知当前页面。双栏阅读由独立生命周期控制器原地切换，不会刷新标签页；设置会写入 `chrome.storage.sync`，因此会随浏览器配置同步。

## Markdown 输出

开启“导出时保留来源元信息”时，单个楼层大致如下：

```markdown
<!-- 来源: https://linux.do/t/example/123#post-3 | 作者: user | 2024-01-01T12:00:00Z -->

正文内容...
```

导出多个已加载楼层时，文件会先写入主题来源，再为每个楼层写入楼层号、作者和链接。关闭元信息后，只保留正文，并用 Markdown 分隔线分隔楼层。

导出范围由当前页面已渲染楼层决定，不会主动遍历服务器上的所有回复；尚未被 Discourse 懒加载出来的楼层不会导出。

## 常见问题

- **弹窗按钮不可用**：确认当前标签页是 `https://linux.do/` 或 `https://www.linux.do/` 下的页面。扩展刚加载或刚更新后，刷新主题页。
- **提示“页面未加载完成”**：关闭弹窗，等待页面完成加载后再打开；必要时刷新页面。
- **看不到楼层按钮**：检查“显示楼层复制 / 下载按钮”是否开启，并确认目标楼层已经滚动加载出来。
- **导出楼层不全**：弹窗导出只处理当前已加载楼层；请先滚动到需要的楼层，让 Discourse 完成懒加载。
- **出现部分失败或 HTTP 429**：插件会对限流请求进行退避重试；仍失败时会提示成功 / 失败数量，可稍后重试。

## 开发

```bash
npm install
npm run build        # esbuild 打包，清空并重建 dist/，同步更新根目录产物
npm run check        # 构建、TypeScript 类型检查、生成脚本语法和 manifest 校验
npm test             # Vitest + jsdom 测试
npm run test:watch   # 测试 watch 模式
npm run lint         # ESLint
npm run format       # Prettier 格式化 src/ 和 test/
npm run format:check # 检查格式化
```

源码入口和职责：

```text
src/
├── common/settings.ts        # 设置、默认值和同步存储
├── content/index.ts          # 页面增强入口
├── content/refresh-state.ts  # 页面增强任务的防抖与重入合并
├── content/buttons.ts        # 楼层复制 / 下载按钮
├── content/base64.ts         # Base64 与“去中文”工具
├── content/post-export.ts    # 单楼层和批量导出
├── content/api-rate-limiter.ts # 批量请求并发与 429 退避
├── content/markdown.ts       # Markdown 规范化与转换
├── content/image-viewer.ts   # 原生风格图片预览查看器
├── content/messages.ts       # popup 与内容脚本通信
├── content/topic-api.ts      # Topic JSON、stream 分页和楼层缓存
├── content/topic-layout-controller.ts # 双栏开关、路由、断点和失败状态
├── content/topic-layout.ts   # 双栏布局、分页、回退与原生操作交接
├── content/topic-state.ts    # URL 与 sessionStorage 阅读状态
├── content/topic-events.ts   # 页面事件桥数据校验
├── content/topic-read-tracking.ts # 可见评论阅读时长上报
├── page/topic-events-bridge.ts # MAIN world Discourse MessageBus 桥
└── popup/index.ts            # 工具栏弹窗
```

新增需要随页面 DOM 更新的普通功能时，实现一个接收 `DiscourseSettings` 的刷新函数，并在 `content/index.ts` 的 `enhancements` 中连同自有 DOM 选择器一起注册。双栏阅读不属于通用 DOM 增强，由 `TopicLayoutController` 单独响应设置、主题路由、桌面断点和主题事件。新增设置项时同步更新设置接口、`SETTING_KEYS`、默认值和 popup 控件。

构建脚本会把 TypeScript 入口打包为浏览器可直接加载的 IIFE，并生成 source map；发布扩展本身不包含运行时 npm 依赖。扩展声明的主要权限为 `activeTab`、`clipboardWrite` 和 `storage`，导出请求使用当前 Linux.do 页面的登录态访问同源接口。
